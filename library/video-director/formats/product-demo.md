# Format: product-demo

A tour that shows what the product does for someone who has not used it.

- **Sources:** the landing page or README pitch, the main docs, and the app itself (scout every
  primary screen). Customer outcomes or numbers only from a source the user gave.
- **Brief defaults:** audience is a prospect or new user; goal is "I see how this helps me";
  length 1.5-3 min; tone confident and friendly (`[confident]`, `[upbeat]`, `[warmly]`); 16:9.
- **Beats:** the problem in one line, then the 3-6 things the product does about it, each as one
  real workflow on screen, ending on the payoff.
- **Shot structure:** title card (product + promise), a problem card, one shot per capability
  (ring the moment the value shows, not the menu that leads there), a payoff shot of a finished
  result, a closing card with the call to action the user wants (try it, book a call, install).
- **Script:** benefits before features ("Find any client in a second. Just type."). No version
  numbers or changelog talk.
- **Demo data:** seed it to look like a real customer's world in the audience's domain, rich
  enough that every screen looks used.
